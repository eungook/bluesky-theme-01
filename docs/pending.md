# 결정 대기

사용자가 정해야 하는 결정의 목록. 사람과 에이전트가 같이 읽는다. 지금은 하지 않기로 한 것은 [later.md](later.md)에 적는다.

## 운영 규칙

- 결정은 두 종류로 나눈다.
  - **막음**: 답에 따라 작업이 크게 달라지거나 되돌리기 비싼 결정. 에이전트는 기본값으로 밀고 가지 말고 **작업 전에 채팅에서 바로 묻는다.** 답이 바로 오지 않으면 이 파일에 적고 해당 작업은 멈춘다.
  - **안 막음**: 틀려도 나중에 고치면 되는 결정. 에이전트는 기본값으로 진행하고, 답변에 "X로 했다, 아니면 말해 달라"를 한 줄로 쓴 뒤 이 파일에 적는다.
- 항목마다 **질문**, **현재 기본값**, **답에 따라 바뀌는 것**을 적는다.
- 결정이 나면 항목을 지우고, 결정 내용은 해당 문서([extension-guidelines.md](extension-guidelines.md) 등)에 기록한다. (이력은 git에 남는다.)
- 사용자가 지금은 정하지 않겠다고 하면 [later.md](later.md)로 옮긴다.
- 작업을 마치는 답변 끝에는 이 파일의 항목을 "결정 대기"로 최대 3개까지, 한 단어로 답할 수 있게 적는다.
- 사람은 새 기능을 시작하기 전이나 큰 커밋 전에 "결정 대기 정리해줘"라고 요청해 이 파일을 점검할 수 있다.

## 목록

### 통합 테마의 어두운 쪽 적용 방식 — 막음

- **질문:** 통합 테마(흑백, 소프트, 노랑, 숲)의 어두운 쪽을 어떻게 적용할까?
  - **A (추천):** 어두운 쪽도 확장이 정한 팔레트로 직접 칠한다. 블루스카이의 "어두운 테마"(어둑함/어두움) 선택과 상관없이 고른 통합 테마가 어두운 색을 정한다. 흑백은 항상 검정, 소프트는 항상 어둑함 색이 된다. 블루스카이의 "어두운 테마" 선택은 효과가 없으므로 숨긴다. "하나의 테마로 통합"한다는 목적에 맞는다.
  - **B:** 블루스카이의 어둑함/어두움 선택은 그대로 두고, 그 위에 노랑/숲의 색조만 입힌다. 흑백/소프트의 어두운 쪽은 바꾸지 않는다. 구현은 쉽지만 "소프트 = 편안 + 어둑함"이 강제되지 않아서, 어둑함은 사용자가 따로 골라야 한다.
- **현재 기본값:** 어두운 쪽은 적용하지 않는다. 색상 테마 섹션은 밝은 테마에서만 보이고, 작은 원의 어두운 쪽 색은 대표색일 뿐이다.
- **먼저 필요한 자료 (사용자 할 일):** A든 B든 어두운 쪽 인라인 배경색이 있어야 한다.
  1. 블루스카이를 "어둑함"으로 두고, 그다음 "어두움"으로 두고, 각각 밝은 테마 때 쓴 수집 코드(`seen` 맵에 인라인 `background-color`를 모으는 코드)를 실행한다. 여러 화면에서 hover한 뒤 `console.table([...seen])` 결과를 알려 준다.
  2. 어두움일 때 `<html>`의 클래스를 알려 준다. (`theme--dim`은 확인됨. 어두움은 `theme--dark`로 추정한다.)
- **답에 따라 바뀌는 것:** A는 어둑함/어두움 각각의 색을 목표 팔레트로 옮기는 치환표(바탕마다 한 벌), 블루스카이 "어두운 테마" 섹션을 숨기는 코드, 색상 테마 섹션의 "밝은 테마에서만 표시" 조건 제거가 필요하다. B는 노랑/숲의 어두운 쪽 치환표만 필요하다.

### 노랑/숲의 색 값 — 안 막음

- **질문:** 노랑(아주 옅은 겨자색 / 아주 어두운 노란색)과 숲(옅은 세이지 그린 / 아주 어두운 녹색)의 색이 의도에 맞는가?
- **현재 기본값:** 눈으로 보지 않고 정한 첫 추정값이다. 노랑 `#f6efcf`, 숲 `#e8efe6`(밝은 쪽 기본 배경). 네 번째 테마를 "숲"으로 고른 것도 제 선택이다.
- **답에 따라 바뀌는 것:** theme.css 위쪽 팔레트 변수만 바꾸면 된다. 테마를 다른 것으로 바꾸려면 [themes.ts](../src/content/themes.ts)의 id와 [i18n.ts](../src/content/i18n.ts)의 이름도 바꾼다.
