# 크롬 확장 개발 가이드라인

블루스카이 웹(`bsky.app`)의 테마 기능을 강화하는 크롬 확장(Manifest V3)을 만들 때의 주의사항과 설계 시 고려사항. 사람과 에이전트 모두 코드를 작성하기 전에 읽는다.

> 상태: 아직 구현 전. 아래 구조와 결정은 초기 방향이며, 실제 구현과 달라지면 이 문서를 같이 고친다.

## 기본 방침

- 런타임/번들러/패키지 매니저는 Bun (자세한 규칙은 루트 [CLAUDE.md](../CLAUDE.md)).
- 확장은 **빌드해서 `dist/`를 로드**하는 방식으로 제공한다. 개발 중에는 `chrome://extensions`에서 "압축해제된 확장 프로그램 로드"로 `dist/`를 가리킨다. 배포 시에는 `dist/`를 zip으로 묶는다.
- Manifest V3는 원격 코드 실행을 금지한다. 모든 코드는 빌드 시점에 번들에 포함해야 하며, CDN 스크립트를 런타임에 불러오지 않는다.

## 권장 구조

```
src/
  content/index.ts      # 콘텐츠 스크립트: 테마 스타일 주입 (iife)
  background/index.ts   # 서비스 워커 (필요할 때만)
  popup/index.html      # 팝업 UI
  popup/popup.ts
  manifest.json
build.ts                # Bun.build + 정적 파일 복사
dist/                   # 빌드 산출물 (git 제외)
```

## 빌드 시 주의할 점

1. **정적 파일은 직접 복사한다.** `bun build`는 JS/CSS/HTML만 처리한다. `manifest.json`, 아이콘 등은 `build.ts`에서 `dist/`로 복사한다. 빌드는 CLI보다 `Bun.build()`를 호출하는 `build.ts`로 통일한다.
2. **출력 파일명을 고정한다.** manifest가 번들 경로를 참조하므로 해시 파일명이 붙으면 깨진다. `naming` 옵션으로 고정하고, HTML 진입점(팝업/옵션)은 번들 후 경로 참조가 맞는지 확인한다.
3. **포맷과 타깃.** 모든 진입점은 `target: "browser"`. 콘텐츠 스크립트는 ES 모듈로 로드되지 않으므로 `format: "iife"`로 낸다. 서비스 워커는 manifest에서 `"type": "module"`을 지정했을 때만 `esm`을 쓴다.
4. **Bun 런타임 API를 확장 코드에 쓰지 않는다.** `Bun.serve`, `bun:sqlite`, `Bun.file` 등은 브라우저에서 동작하지 않는다. 빌드 스크립트(`build.ts`)에서만 쓴다.
5. **개발 중 리로드.** `Bun.serve`의 HMR은 확장 페이지에서 쓸 수 없다. `bun build --watch` 또는 `build.ts`의 watch 모드로 재빌드하고, 확장 새로고침은 `chrome://extensions`에서 하거나 별도 리로드 스크립트를 둔다.
6. **타입.** `@types/chrome`를 설치해 `chrome.*` API 타입을 쓴다.

## 테마 기능 설계 시 고려할 점

- **블루스카이 웹앱의 DOM은 불안정하다.** React Native Web 기반이라 클래스명이 해시되거나 배포마다 바뀔 수 있다. 클래스 선택자에 의존하지 않는다.
- **선택자 우선순위:** `role` 등 시맨틱 속성과 구조 → `<html>` 테마 클래스 → (번역되지 않는 경우에 한해) `aria-label`. 클래스명은 쓰지 않는다. 설정 화면(`/settings/appearance`)을 확인한 결과 색이 CSS 변수가 아니라 요소의 인라인 `rgb(...)`로 지정되어 있어서, 변수 오버라이드가 항상 통하는 것은 아니다. 화면마다 직접 확인한다.
- **`aria-label`은 번역된다.** 사이트 언어에 따라 바뀌므로 선택자로 쓰지 않는다. (예: 색상 모드 `radiogroup`은 라벨이 아니라 "페이지에서 처음 나오는 radiogroup"으로 찾는다.)
- **깜빡임(FOUC) 방지.** 콘텐츠 스크립트는 `run_at: "document_start"`로 두고, `<style>`을 가능한 빨리 주입한다.
- **설정 저장.** `chrome.storage.sync`에 저장한다. 팝업/옵션 페이지에서 바꾸면 콘텐츠 스크립트가 `chrome.storage.onChanged`로 즉시 반영한다. 별도 메시지 패싱은 필요할 때만 쓴다.
- **권한 최소화.** `host_permissions`는 `https://bsky.app/*`로 한정하고, `permissions`는 `storage` 등 꼭 필요한 것만 선언한다.
- **깨짐에 대비한다.** 블루스카이 쪽 변경으로 선택자가 깨질 수 있다. 선택자는 한 곳(상수 모듈)에 모아 두고, 깨졌을 때 고칠 위치가 명확하도록 한다.

## 블루스카이 DOM 메모

직접 확인한 내용만 적는다. (로그인이 필요한 화면은 사용자가 DevTools에서 outerHTML을 복사해 준 것을 바탕으로 한다. 에이전트가 로그인 화면에 직접 접근하지 않는다.)

- **현재 테마:** `<html class="theme--light">`, `<html class="theme--dim">` 등으로 표시된다. 시스템 모드일 때도 OS 설정에 따라 이 클래스가 자동으로 바뀐다. 따라서 `theme--light` 여부만 보면 "시스템 모드" 분기를 따로 만들 필요가 없다.
- **밝은 테마 스타일:** 사용자가 DevTools에서 확인한 값으로, 블루스카이는 `html.theme--light, html.theme--light body, html.theme--light #root { background-color: white; --text: black; --background: white; --backgroundLight: #DCE2EA; }`로 지정한다. 확장의 [theme.css](../src/content/theme.css)는 같은 요소를 더 높은 specificity(`html.theme--light[data-bt-light-theme="comfort"]`)로 덮어써서 `!important` 없이 이긴다. 선택이 없을 때(최초 설치 등)의 기본값은 "밝음"이라 `data-bt-light-theme`이 `"comfort"`일 때만 적용한다.
  - **배경은 인라인 style로도 지정된다:** 대부분의 영역은 요소의 `style="background-color: rgb(255, 255, 255);"`로 칠해져서 위 규칙만으로는 바뀌지 않는다. 그러나 인라인 style은 스타일시트의 `!important`로 덮어쓸 수 있으므로 JS 없이 CSS 주입만으로 해결된다. 요소는 불안정한 원자 클래스(`r-xxxx`) 대신 `[style*="background-color: rgb(255, 255, 255)"]` 속성 선택자로 고른다. 빨간색으로 시험해 적용 범위를 확인했다.
  - **색은 CSS가 아니라 JS 테마 팔레트에서 온다.** 블루스카이의 팔레트(`@bsky.app/alf`의 `createThemes`)가 만든 값을 react-native-web이 인라인 style로 넣는다. 그래서 CSS 파일을 분석해도 색을 알 수 없고, 실제 DOM의 인라인 색을 수집해야 한다. hover는 마우스를 올릴 때 인라인 값이 다른 팔레트 색으로 바뀌는 것으로 보이며(소스에서 직접 확인하지는 못했다), 속성 선택자는 값이 바뀌어도 그대로 걸린다.
  - **밝은 테마에서 수집한 인라인 배경색** (설정, 프로필, 피드 등 여러 화면을 hover하며 수집): `rgb(239,242,246)` 351곳(보조 면), `rgb(249,250,251)` 116곳(hover), `rgb(255,255,255)` 92곳(기본), `rgb(236,72,153)` 분홍, `rgb(0,106,255)` 파랑, `rgb(242,242,242)` 7곳(용도 미확인), `rgba(0,0,0,0.5)` 오버레이, 투명. 흰색 계열 세 가지(255 / 249,250,251 / 239,242,246)만 톤다운 대상이다.
  - **톤다운 방식:** 원래 색마다 바꿀 색을 [theme.css](../src/content/theme.css)의 `--bt-bg-0/25/50`에 hex로 직접 적는 단순 치환이다. 흰색을 전부 같은 색으로 바꾸면 hover 색(249,250,251)이 기본 배경보다 밝아져 hover 때 오히려 번쩍이므로, 기본 > hover > 보조 면의 밝기 순서가 유지되게 값을 정한다. (참고: 기본색의 각 채널에 `색조/255`를 곱하면 이 순서가 자연스럽게 유지된다.) 새 색이 필요하면 `--bt-bg-*` 변수와 규칙을 추가한다.
  - **범위 결정(사용자):** 인라인 값을 치환하는 방식을 유지하고, 지금은 밝은 테마의 배경만 바꾼다. 현재 동작으로 충분하다고 판단했다. 테두리, 글자, 아이콘 채움, 그림자, 어두운 테마(dim/dark)는 하지 않는다. 필요해지면 그 속성의 인라인 값을 따로 수집해 치환표에 추가하는 식으로 넓힌다. (한계: 값의 문자열 형식에 의존하고, 수집하지 못한 색은 바뀌지 않는다.)
  - 같은 이유로 흰색인 다른 요소(예: 설정 화면의 선택 썸)도 함께 바뀐다.
  - `:root`에는 `--rc-*` 변수(`--rc-focus-color: #08f` 등)도 있으나 아직 건드리지 않았다.
- **언어:** 블루스카이 앱의 언어는 `<html lang="ko">`로 확인한다(사용자 확인). 확장의 문구는 브라우저 UI 언어를 따르는 `chrome.i18n`이 아니라 이 값을 기준으로 [i18n.ts](../src/content/i18n.ts)에서 고른다. 지원 언어는 en, ko이고 그 밖의 언어나 값이 없으면 en이다. `ko-KR` 같은 지역 코드는 앞부분만 본다. 새 문구는 모든 언어에 같이 추가한다. (실제 확인: 값은 `ko`, `en`처럼 지역 코드 없는 형식이고, 앱 안에서 언어를 바꾸면 새로고침 없이 이 속성이 바뀐다. 그래서 `lang` 속성을 관찰하다가 바뀌면 섹션을 다시 그린다. 한국어, 영어, 지원하지 않는 언어(일본어)에서 문구가 의도대로 나오는 것도 확인했다.)
- **이전 화면이 숨겨진 채 남을 수 있다:** 화면을 이동했다가 돌아오면 같은 화면이 DOM에 여러 개 있을 수 있어서, `document.querySelector`로 첫 번째 요소를 고르면 숨겨진 옛 화면을 잡을 수 있다. 요소를 고를 때는 `checkVisibility()`로 보이는 것만 대상으로 한다. (보이는 요소만 고르도록 고친 뒤 "설정 > 모양 → 프로필 → 설정 > 모양" 재진입 시 섹션이 사라지던 증상이 해결되어 확인했다.)
- **SPA:** 라우트 이동 시 페이지가 새로 로드되지 않는다. `MutationObserver`로 화면이 그려지는 시점을 감지한다.
- **설정 > 모양 (`/settings/appearance`):**
  - 섹션 구조: `div > [아이콘+제목 행, div > radiogroup]`. radiogroup은 `[썸, 옵션 래퍼 × N]` 자식을 가진다.
  - 썸은 항상 있지 않다: 새로고침 직후에는 레이아웃 측정 전이라 썸이 없다가 나중에 렌더링된다. radiogroup의 첫 번째 자식이 썸이라고 가정하지 말고, radio를 품지 않은 자식을 썸으로 찾는다.
  - **테마를 바꾸는 중에는 인라인 색이 한꺼번에 갱신되지 않는다.** 다크 → 라이트 전환 중에 트랙과 옵션 글자색은 라이트로 바뀌었는데 제목/아이콘 색은 아직 다크(흰색)인 순간이 있다. 이때 원본을 복제하면 어두운 색이 그대로 박제되어 밝은 배경에서 글자가 안 보인다. 그래서 이 섹션은 원본을 복제하지 않고 [light-theme-section.ts](../src/content/light-theme-section.ts)에서 직접 만든다. 이 섹션은 밝은 테마에서만 보이므로 밝은 테마 팔레트만 가지고 있으면 된다.
  - 선택 상태: `aria-pressed`는 항상 `"false"`라서 쓸 수 없다. 선택은 썸(`translateX`)과 글자색으로만 표현된다. 선택 글자색은 제목 글자색과 같다.
  - 썸의 `width`/`translateX`는 JS가 px로 계산한다. 직접 만든 섹션은 `calc((100% - 8px) / N)`, `translateX(calc(4px + i*100%))`로 비율 계산한다.
  - "색상 모드" 섹션은 항상 있고, "어두운 테마" 섹션은 어두운 테마일 때만 렌더링된다. 컨테이너 자식 순서는 `[색상 모드] [div > 어두운 테마] [div > 구분선 + 글꼴 + 글꼴 크기]`.
  - 색(인라인): 트랙/썸/비선택 글자 — 밝음 `rgb(239,242,246)`/`#fff`/`rgb(135,152,176)`, 어둑함(dim) `rgb(34,46,63)`/`rgb(21,29,40)`/`rgb(88,108,137)`.
- **React 밖의 요소:** 우리가 삽입한 노드는 React가 관리하지 않으므로 리렌더링 때 사라질 수 있다. 관찰자가 계속 확인해서 다시 삽입한다.
- **흰 배경을 `theme.css`가 문자열로 찾는다:** 직접 만든 요소의 흰 배경도 `style` 속성에 `background-color: rgb(255, 255, 255)` 형식(콜론 뒤 공백)으로 써야 `[style*="..."]` 선택자에 걸린다.

## 로컬에서 확인하는 방법

1. `bun run build` (개발 중에는 `bun run dev`로 변경 시 자동 재빌드)
2. `chrome://extensions` → 개발자 모드 → "압축해제된 확장 프로그램을 로드합니다" → `dist/` 선택
3. `https://bsky.app/settings/appearance`에서 밝음 모드로 두고 확인. 코드를 바꾼 뒤에는 확장 새로고침과 페이지 새로고침이 둘 다 필요하다.

## 수정 시 규칙

- 위 내용과 다른 방향으로 구현하게 되면 코드만 고치지 말고 이 문서도 함께 갱신한다.
- 새로 알게 된 블루스카이 DOM/변수 정보(안정적인 선택자, CSS 변수 이름 등)는 이 문서나 `docs/` 아래 별도 문서에 기록한다.
